# Фронтенд. Техническое задание исполнителю

Этот документ — рабочее задание для исполнителя, который делает веб-интерфейс.
Бэкенда на момент работы нет: всё собирается на моках, повторяющих
`04-API-CONTRACT.md`. Контракт — закон, отступления от него ломают второй этап.

Читать вместе с: `01-TZ.md` (что за бизнес), `04-API-CONTRACT.md` (формат данных).

## 2. Базовые требования к интерфейсу

### 2.1. Что это за пользователь

Кладовщик в цеху, менеджер в потоке звонков, финансист с таблицами на 10 000
строк. Не аудитория лендингов. Отсюда:

- **Плотность важнее воздуха.** Строка таблицы — 36–40 px, не 64.
- **Минимум кликов на частую операцию.** Приёмка на складе должна закрываться
  с клавиатуры и сканера, без мыши.
- **Клавиатура — полноценный способ работы.** Tab по полям в логичном порядке,
  Enter — подтверждение, Esc — отмена, стрелки в выпадающих списках.
- **Цифры выровнены по правому краю**, моноширинные табличные цифры
  (`font-variant-numeric: tabular-nums`), разряды разделены.
- **Никаких «красиво, но непонятно».** Статус — текст плюс цвет, не только цвет.

### 2.2. Вёрстка — жёсткие правила

- Соседние элементы выравниваются через **flex/grid**. `position: absolute`
  с подогнанными пикселями (`left: 58px`) не применяется. Исключение — оверлеи,
  выпадающие меню и тултипы, где абсолютное позиционирование по природе задачи.
- Ширины — через сетку и `minmax`, не магическими числами.
- Отступы — только из шкалы токенов (4/8/12/16/24/32/48).
- Любой текст переменной длины не должен ломать раскладку: проверяется на
  узбекской локали, где подписи длиннее русских на 15–30%.

### 2.3. Адаптив

Три размера, все обязательны:

| Ширина | Поведение |
|---|---|
| ≥1440 | сайдбар развёрнут, таблицы во всю ширину, боковая панель деталей |
| 768–1439 | сайдбар свёрнут в иконки, детали — модальным окном |
| ≤360 | одна колонка, таблицы превращаются в карточки, действия — нижняя панель |

**Перед сдачей любого экрана — скриншоты на 360 и 1440, во всех состояниях
компонента (сайдбар свёрнут/развёрнут, светлая/тёмная тема).** Смотреть самому,
что ничего не выехало за контейнер и не обрезалось.

### 2.4. Дизайн-направление

Инструментальный интерфейс промышленного учёта: спокойный, плотный, без
декоративных излишеств. Ориентир — панель управления, а не маркетинговый сайт.

Токены (CSS-переменные, обе темы):

```
--bg, --bg-subtle, --surface, --border, --border-strong
--text, --text-muted, --text-inverse
--accent (действие), --accent-hover, --accent-subtle
--success, --warning, --danger, --info  + каждый с -subtle фоном
--radius-sm 4px, --radius-md 6px, --radius-lg 10px
--space-1..8 (4/8/12/16/24/32/48/64)
--font-sans, --font-mono
```

Типографика: один шрифт без засечек с хорошей кириллицей и узбекской латиницей
(Inter или системный стек). Шкала: 12 / 13 / 14 / 16 / 20 / 24 / 32.
Основной текст интерфейса — 14, таблицы — 13, подписи — 12.

Контраст: обычный текст ≥ 4.5:1, крупный ≥ 3:1 — в обеих темах. Проверяется,
а не предполагается.

Состояния обязательны у каждого интерактивного элемента: обычное, наведение,
фокус (видимое кольцо), нажатие, заблокировано, загрузка, ошибка.

Запрещено: фиолетово-синие градиенты, стеклянные размытия, тени в несколько
слоёв, иконки-эмодзи вместо иконок, анимации дольше 200 мс на рабочих действиях.

### 2.5. Состояния экранов

Каждый экран со сложными данными обязан иметь все пять:

1. **Загрузка** — скелет той же формы, что и контент, без прыжка раскладки.
2. **Пусто** — что это за экран, почему пусто, кнопка первого действия.
3. **Ошибка** — что произошло, что делать, кнопка «Повторить».
4. **Нет прав** — нейтральное сообщение, без технических кодов.
5. **Данные** — собственно контент.

### 2.6. Локализация

- Переключатель ru/uz в шапке, выбор сохраняется в профиле.
- Ни одной строки текста в коде — всё через словари.
- Двуязычные поля с сервера (`nameRu`/`nameUz`) выбираются по текущей локали
  с запасным вариантом на другой язык, если выбранный пуст.
- Формат чисел, дат и валюты — по локали. Валюта по умолчанию UZS,
  отображение: `48 500 000 сум`, разделитель разрядов — неразрывный пробел.
- Сгенерированные документы запрашиваются в той же локали.

## 3. Оболочка приложения

### 3.1. Шапка

Слева направо: кнопка сворачивания сайдбара · переключатель компании ·
глобальный поиск · переключатель языка · тема · колокольчик уведомлений ·
меню пользователя.

**Переключатель компании** — принципиальный элемент. Пользователь может иметь
доступ к торговой компании, к заводу или к обеим. Выбранная компания уходит
в заголовок `X-Company-Id` каждого запроса. При переключении весь кэш данных
сбрасывается — иначе на экране окажутся данные другой компании, а это прямое
нарушение требования 3.2 Спецификации.

Если у пользователя доступна одна компания — переключатель показывается как
статичная подпись, без выпадающего списка.

**Глобальный поиск** (`Ctrl/Cmd + K`): ищет по номерам заказов, документов,
партий, серийных номеров, клиентам и номенклатуре. Результаты сгруппированы
по типу, переход по Enter.

### 3.2. Сайдбар

Разделы (пункт виден, только если есть соответствующее право):

```
Главная
Продажи        · Заказы · Отгрузки · Прайс-листы
Склад          · Остатки · Движения · Приёмка · Инвентаризация
               · Партии и серии · Потребность в закупке
Производство   · Заказы · Календарь · Техкарты · Отклонения
Финансы        · Операции · Дебиторка · Кредиторка · Бюджеты
               · KPI · Отчёты
Документы      · Документы · Шаблоны · Типы документов
CRM            · Лиды · Сделки · Клиенты · Задачи · Отчёты
Администрирование · Пользователи · Роли и права · Справочники
               · Настройки · Журнал действий
```

Состояния: развёрнут (иконка + подпись, 240 px), свёрнут (иконки, 64 px,
подпись во всплывающей подсказке). Состояние сохраняется между сессиями.
Активный раздел подсвечен, родительский пункт раскрыт.

### 3.3. Уведомления

Колокольчик со счётчиком непрочитанных. Панель: список с типом, текстом,
временем, переходом к объекту. Фильтр «только непрочитанные», кнопка
«прочитать все». Обновление — по WebSocket, при его недоступности —
опрос раз в 60 секунд.

## 4. Общие компоненты

### 4.1. DataTable — основа половины системы

Обязательные возможности:

- серверная пагинация, сортировка, фильтрация (всё через query-параметры URL);
- **состояние таблицы живёт в URL** — ссылку на отфильтрованный список можно
  переслать коллеге, и он увидит то же самое;
- выбор колонок и их порядок, сохранение набора в профиль пользователя;
- закрепление первых колонок при горизонтальной прокрутке;
- виртуализация строк от 200 записей;
- массовое выделение и групповые действия;
- строка итогов (сумма, количество) — там, где имеет смысл;
- экспорт видимого набора в Excel/CSV;
- клик по строке — переход в карточку, среднюю кнопку мыши — в новой вкладке;
- плотность на выбор: компактная / обычная;
- на ≤768 px таблица перестраивается в список карточек.

Типы колонок и их отображение:

| Тип | Как выводится |
|---|---|
| `money` | вправо, tabular-nums, разделители разрядов, валюта в заголовке |
| `qty` | вправо, до 6 знаков, лишние нули не показываются, единица рядом |
| `date` | по локали, относительное время в подсказке |
| `status` | бейдж: цвет + текст |
| `link` | переход к связанному объекту |
| `user` | имя, инициалы в кружке |

### 4.2. Панель фильтров

Единая для всех списков: строка поиска, период (с пресетами «сегодня»,
«неделя», «месяц», «квартал»), специфичные для сущности фильтры, кнопка
«Сбросить», счётчик активных фильтров. Сохранённые наборы фильтров — по имени.

### 4.3. Подборщики (пикеры)

**ItemPicker** — выбор номенклатуры. Поиск по коду, наименованию, штрихкоду
и характеристикам. В строке результата: код, наименование, характеристики
(марка, диаметр, толщина), доступный остаток, единица, цена. Позиции с нулевым
доступным — показываются, но помечены. Поддержка ввода со сканера.

**PartnerPicker** — клиент/поставщик. Поиск по наименованию, ИНН, телефону.
В строке: наименование, ИНН, текущий долг, признак превышения лимита долга.

**BatchPicker** — партия при списании. Показывает номер, дату прихода, остаток,
себестоимость. По умолчанию подсвечивает подбор FIFO, но даёт выбрать вручную,
если есть право.

Все пикеры: работа с клавиатуры, дебаунс 250 мс, отмена предыдущего запроса,
виртуализация длинных списков, пустое состояние с кнопкой «Создать новый».

### 4.4. Поля ввода

- **MoneyInput** — разделители разрядов при вводе, валюта справа, до 4 знаков.
  Хранит и отправляет строку, не число.
- **QtyInput** — до 6 знаков, выбор единицы измерения рядом, пересчёт в базовую
  единицу в подсказке.
- **ScanInput** — принимает быстрый ввод со сканера (сканер эмулирует
  клавиатуру), ловит завершающий Enter, не теряет фокус между сканированиями,
  показывает последние отсканированные позиции.

### 4.5. StatusBadge

Единая карта статусов на всё приложение: цвет, иконка, текст (двуязычно).
Серый — черновик, синий — в работе, жёлтый — ожидание/согласование, зелёный —
завершено, красный — отменено/ошибка, оранжевый — просрочено.

### 4.6. Обработка ошибок API

| Код | Поведение фронта |
|---|---|
| 400 | подсветить поля из `error.details[].field`, показать сообщения |
| 401 | попытка refresh, при неудаче — на страницу входа с возвратом |
| 403 | экран/блок «Нет прав», без технических подробностей |
| 404 | «Запись не найдена или недоступна» |
| 409 | диалог «Запись изменена другим пользователем» с кнопками «Перезагрузить» / «Показать отличия» |
| 422 | модальное окно с бизнес-объяснением (нехватка остатка — с таблицей дефицита и кнопкой «Создать производственный заказ») |
| 429 | «Слишком много запросов, повторите через N секунд» |
| 500 | «Ошибка сервера», кнопка «Повторить», `requestId` мелким шрифтом для поддержки |

Каждое изменяющее действие отправляет `Idempotency-Key`; при обрыве сети
запрос повторяется автоматически с тем же ключом.

### 4.7. Права в интерфейсе

Кнопки и пункты строятся по `permissions` объекта и списку прав из `/auth/me`.
Недоступное **скрывается**, а не отображается заблокированным — кроме случаев,
когда пользователю полезно знать о существовании действия; тогда блокировка
с подсказкой-причиной.

Важно понимать исполнителю: скрытие кнопки — это удобство, а не защита.
Сервер проверяет право повторно. Не пытаться «оптимизировать» проверки.

Дальше — по разделам. Для каждого: что показывает, состав таблицы, фильтры,

### 5.1. Вход

Поля: логин, пароль, «запомнить меня». Ошибки: неверные данные (без уточнения,
что именно неверно), учётная запись заблокирована, слишком много попыток.
Переключатель языка доступен до входа. После входа — на главную; если был
сохранён адрес — возврат на него.

### 5.2. Главная

Набор виджетов зависит от роли, приходит из `GET /dashboard/summary`.

| Роль | Виджеты |
|---|---|
| Собственник | продажи за период (график), прибыль и маржа, дебиторская задолженность с просрочкой, остатки деньгами, производство план/факт, критические остатки, топ клиентов, топ позиций |
| Руководитель производства | заказы в работе, просроченные этапы, загрузка участков, брак за период, потребность в материалах |
| Кладовщик | задачи приёмки и отгрузки на сегодня, позиции ниже минимума, незакрытые инвентаризации, последние операции |
| Финансист | остатки по кассам и счетам, платежи на сегодня, просроченная дебиторка, операции на согласовании, превышение бюджета |
| Менеджер | мои сделки по стадиям, задачи на сегодня и просроченные, мои заказы по статусам, мой KPI за месяц |

Виджет: заголовок, значение, динамика к прошлому периоду, переход к
отфильтрованному списку. Расположение — сетка, перестраивается под ширину.
Период сводки переключается (сегодня / неделя / месяц / квартал).

### 5.3. Продажи

#### 5.3.1. Список заказов

Колонки: номер, дата, клиент, менеджер, сумма, оплачено, статус заказа,
статус оплаты, статус отгрузки, срок поставки, склад, маржа (по праву).

Фильтры: период, статус, статус оплаты, статус отгрузки, клиент, менеджер,
склад, «только просроченные», «только мои», диапазон суммы.

Итоги: количество заказов, сумма, оплачено, долг, маржа.

Действия из списка: создать, открыть, копировать, экспорт.
Групповые: смена ответственного, экспорт выбранных.

Просроченные по оплате — строка с оранжевой отметкой слева и подсказкой
«просрочено на N дней». Не только цветом: отметка плюс значок.

#### 5.3.2. Карточка заказа

**Шапка:** номер, дата, статус (все три оси), клиент со ссылкой, менеджер,
склад, тип цены, валюта, срок поставки, плановая дата оплаты.

**Панель действий** (видимость — по `permissions`): Подтвердить · Резервировать ·
Снять резерв · В производство · Комплектация · Отгрузить · Закрыть · Отменить ·
Создать документ · Печать.

**Таблица позиций:** номенклатура (с характеристиками), количество, единица,
цена, скидка, сумма без НДС, НДС, сумма, склад, доступно, резерв,
себестоимость и маржа (по праву), связанный производственный заказ.

Логика строк:
- при добавлении позиции — запрос доступности; если доступного меньше
  запрошенного, строка помечается и показывается дефицит с вариантами:
  уменьшить количество, взять с другого склада, создать производственный заказ;
- цена подставляется из `/sales/price` с учётом клиента и типа цены;
  ручная правка — по праву, с обязательным комментарием, изменённая цена
  визуально отмечена;
- суммы пересчитываются на клиенте для мгновенной обратной связи, но
  **итог по заказу приходит с сервера** — расхождение округлений в деньгах
  недопустимо.

**Боковая панель / вкладки:** Резервы · Отгрузки · Документы · Платежи ·
Производственные заказы · Задачи · Файлы · История изменений.

**Блок оплаты:** сумма заказа, оплачено, остаток, плановая дата, просрочка,
список связанных платежей.

**Блок маржи** (по праву): выручка, себестоимость, маржа в сумме и процентах.

#### 5.3.3. Отгрузки

Список: номер, дата, заказ, клиент, склад, позиций, сумма, статус, ответственный.
Карточка: позиции с партиями и серийными номерами, вес и объём, документы,
подтверждение отгрузки.

#### 5.3.4. Прайс-листы

Таблица: позиция, тип цены, цена, валюта, период действия. Массовое изменение
(на процент, на сумму) для выбранных позиций с предпросмотром результата.
Импорт и экспорт Excel. Отдельная вкладка индивидуальных цен по клиентам.

---

### 5.4. Склад

#### 5.4.1. Остатки

Главный экран кладовщика и один из самых нагруженных.

Колонки: позиция (код, наименование), характеристики (марка, диаметр, толщина,
длина), склад, зона, место, партия, серийный номер, физический остаток, резерв,
доступно, единица, себестоимость, сумма, минимум, критический уровень.

Фильтры: склад, зона, группа номенклатуры, позиция, партия, характеристики
(диапазоны диаметра, толщины, длины, марка), «ниже минимума», «ниже
критического», «только с резервом», «скрыть нулевые».

Режимы группировки — переключателем: по позициям · по складам · по партиям ·
по местам хранения. Дерево со сворачиванием групп и промежуточными итогами.

Итоги: позиций, общее количество по единицам, сумма.

Действия: приход, перемещение, списание, резерв, печать этикеток, экспорт.
Из строки — быстрый переход к движениям этой позиции и к прослеживаемости партии.

Подсветка: ниже критического — красная отметка, ниже минимума — жёлтая.
Отметкой и значком, не только заливкой.

#### 5.4.2. Движения

Журнал: дата и время, тип операции, позиция, партия, серия, откуда, куда,
количество, единица, сумма, документ-основание, контрагент, автор, комментарий.

Фильтры: период, тип операции, склад, позиция, партия, серийный номер,
контрагент, автор, документ.

Действия: открыть карточку движения, перейти к документу-основанию, сторно
(по праву, с обязательной причиной). Сторнированные и сторнирующие строки
визуально связаны и помечены.

#### 5.4.3. Приёмка

Экран рассчитан на работу со сканером и клавиатурой.

Шапка: склад, зона, поставщик, документ поставщика, дата.
Далее — поле сканирования в постоянном фокусе.

Логика: скан кода → позиция найдена → строка добавлена с количеством 1 →
количество правится с клавиатуры → Enter → фокус возвращается в поле скана.
Повторный скан той же позиции увеличивает количество существующей строки,
а не создаёт новую.

Если позиция партионная — запрашивается номер партии (или генерируется),
дата, сертификат (файл). Серийные — ввод или скан каждого номера, счётчик
«введено N из M».

Ручное добавление позиции — через ItemPicker, для случаев без кода.
Фото приёмки прикрепляются к операции.

Проведение: сводка (позиций, количество, сумма), кнопка «Провести».
До проведения документ сохраняется черновиком и не меняет остатки.

#### 5.4.4. Перемещение, выдача в производство, возврат, списание

Общая форма: откуда, куда (склад/зона/место или производственный заказ),
таблица позиций с подбором партий, причина (для списания — обязательна),
комментарий, файлы. Проверка доступного при добавлении позиции.

Выдача в производство дополнительно: выбор производственного заказа и этапа,
подстановка плановой потребности из техкарты с возможностью правки.

#### 5.4.5. Инвентаризация

Мастер из трёх шагов:

1. **Создание** — склад, зона, отбор позиций (все / группа / выборочно),
   режим блокировки операций (блокировать зону / учитывать после пересчёта).
2. **Подсчёт** — таблица: позиция, партия, место, учётное количество,
   фактическое, расхождение, причина. Ввод с клавиатуры или сканированием.
   Учётное количество по умолчанию скрыто (переключатель «слепой пересчёт») —
   иначе считающий просто переписывает ожидаемое.
3. **Утверждение** — сводка расхождений: недостачи, излишки, суммы.
   Утверждение создаёт складские операции автоматически.

#### 5.4.6. Партии и серийные номера

Список партий: номер, позиция, дата, поставщик или производственный заказ,
приход, остаток, себестоимость, срок годности, сертификат.

**Карточка прослеживаемости** — отдельный экран, важный для приёмки:
сверху карточка партии, ниже две ветви — «откуда пришла» и «куда ушла»,
в виде дерева событий с датами, документами и количествами. Каждый узел —
ссылка на документ. Есть кнопка «Печать истории партии».

#### 5.4.7. Потребность в закупке

Таблица: позиция, доступно, минимум, критический уровень, открытые резервы,
плановый расход по запущенным производственным заказам, дефицит, рекомендуемое
количество к закупке, последний поставщик, последняя цена закупки.

Сортировка по умолчанию — по срочности. Экспорт в Excel и отправка
ответственному в Telegram.

### 5.5. Производство

#### 5.5.1. Список заказов

Колонки: номер, продукция, количество план/факт, единица, срок, статус,
ответственный, участок текущего этапа, прогресс, заказ продажи, просрочка.

Фильтры: период, статус, продукция, ответственный, участок, «только
просроченные», «только мои», связь с заказом продажи.

Представления — переключатель:
- **таблица** — по умолчанию;
- **доска** — колонки по статусам, карточки заказов, перетаскивание при наличии
  права (перетаскивание вызывает тот же эндпоинт действия, что и кнопка);
- **календарь** — см. ниже.

#### 5.5.2. Карточка производственного заказа

**Шапка:** номер, продукция, количество план/факт, годный выпуск, брак, отход,
срок, статус, ответственный, техкарта с версией, связанный заказ продажи,
прогресс полосой.

**Действия:** Запланировать · Запустить · Приостановить · Возобновить ·
Завершить выпуск · Закрыть · Отменить · Рассчитать себестоимость · Документы.

**Вкладка «Этапы»:** порядок, название, участок, ответственный, плановые даты,
фактические запуск/остановка/завершение, длительность план/факт, статус,
комментарии, фото. Кнопки управления этапом прямо в строке. Разворот строки —
история событий этапа с причинами простоев.

**Вкладка «Материалы»:** позиция, план, выдано, израсходовано, возвращено,
отклонение (в количестве и деньгах), партии списания. Кнопки «Выдать со склада»
и «Вернуть на склад». Отклонение сверх допустимого — отмечено.

**Вкладка «Выпуск»:** годная продукция, брак, отход, полуфабрикаты — с датами,
партиями, исполнителями, причинами брака и фотографиями. Форма фиксации выпуска.

**Вкладка «Себестоимость»:** материалы, полуфабрикаты, прямые затраты,
переделки, итог, себестоимость единицы. История расчётов с датами и авторами.
Видно по праву.

**Вкладка «Отклонения»:** простои, перерасход, брак, задержки — с причинами,
длительностью и суммой потерь.

**Вкладка «Документы» и «История изменений».**

#### 5.5.3. Календарь производства

Ось времени по горизонтали, участки по вертикали. Полосы — этапы заказов,
цвет по статусу. Масштаб: день / неделя / месяц. Пересечения по загрузке
участка подсвечены. Клик — карточка этапа, перетаскивание — перенос плановых
дат (по праву).

Под календарём — полоса загрузки каждого участка в процентах от фонда времени.

#### 5.5.4. Техкарты

Список: продукция, версия, статус, дата ввода в действие, автор.
Редактор карты: этапы (порядок, участок, норматив времени, процент отхода,
признак параллельности), материалы по этапам (позиция, норма на единицу,
признак автосписания). Предпросмотр «на 100 единиц продукции» — сколько
материалов и времени потребуется.

Правка активной карты создаёт новую версию. Запущенные заказы остаются на
своей версии — это должно быть видно в интерфейсе явной подписью.

#### 5.5.5. Отклонения

Журнал: дата, заказ, этап, тип (простой, перерасход, брак, задержка), причина,
длительность, сумма, кто зафиксировал. Фильтры по типу, причине, участку,
периоду. Сводка сверху: количество и сумма по типам.

### 5.6. Финансы

#### 5.6.1. Операции

Колонки: дата, номер, тип, счёт, сумма, валюта, сумма в базовой валюте, статья,
контрагент, основание, статус, автор, согласующий.

Фильтры: период, тип, счёт, статья, контрагент, статус, валюта, диапазон суммы,
«ждут моего согласования».

Итоги: поступления, выбытия, сальдо по выбранному периоду.

Действия: создать поступление / выбытие / перемещение, отправить на
согласование, согласовать, отклонить, провести, сторно.

**Форма операции:** тип, дата, плановая дата, счёт (и счёт-получатель для
перемещения), сумма и валюта, курс (подставляется по дате, правится по праву),
статья ДДС, контрагент, основание (заказ / производственный заказ / документ /
договор — с подборщиком), комментарий, файлы (фото чека, скан накладной).

Проведённая операция открывается только на чтение, с кнопкой «Сторнировать».
Попытка редактирования должна быть невозможна в интерфейсе — не заблокированное
поле, а режим просмотра.

#### 5.6.2. Дебиторская и кредиторская задолженность

Таблица: контрагент, всего долг, текущий, просрочка 1–7, 8–30, 31–60, 60+,
дата последней оплаты, ответственный менеджер, лимит долга, превышение.

Разворот строки — расшифровка по заказам и документам с датами и суммами.
Действия: напомнить (уведомление менеджеру), создать документ, перейти к клиенту.
Фильтр «только просроченные», сортировка по сумме просрочки.

#### 5.6.3. Бюджеты

Экран план-факт: строки — статьи (иерархией), колонки — план, факт, отклонение
в сумме и процентах, исполнение полосой. Период и подразделение — в фильтрах.
Превышение порога — отмечено. Разворот статьи до операций, из которых сложился
факт. Редактирование планов — таблицей с вводом по ячейкам.

#### 5.6.4. KPI

Список схем расчёта (настройка: показатель, период, план, шкала, база бонуса)
и результаты: сотрудник, период, показатель, план, факт, процент выполнения,
бонус, статус утверждения.

ОТКРЫТО: правила от заказчика не получены. Экран делается на настраиваемой
схеме; до получения правил заполняется схемой-примером.

#### 5.6.5. Отчёты

Общий каркас: выбор отчёта → параметры (период, компания, подразделение,
склад, контрагент, менеджер) → построение → таблица с итогами → экспорт
Excel/CSV, печать PDF.

Колонки таблицы берутся из ответа сервера, а не зашиваются в код.

Состав: ДДС, остатки по кассам и счетам, дебиторка, кредиторка, план-факт
бюджета, прибыль и убытки, маржа (по заказу / товару / клиенту / менеджеру),
KPI, сводный управленческий отчёт.

Тяжёлые отчёты строятся фоновой задачей: экран показывает прогресс и уведомляет
о готовности, не блокируя работу.

### 5.7. Документы

#### 5.7.1. Список

Колонки: номер, тип, дата, контрагент, основание, сумма, статус, автор,
согласующий, версия. Фильтры: тип, период, контрагент, статус, автор, основание.
Действия: создать, скачать DOCX/PDF, отправить на согласование, согласовать,
вернуть, подписать, отменить.

#### 5.7.2. Карточка документа

Шапка: номер, тип, дата, статус, контрагент, основание со ссылкой, сумма.
Предпросмотр сформированного документа (PDF во встроенном просмотрщике).
Панель: скачать DOCX, скачать PDF, печать, перевыпустить, сменить язык.

Вкладки: Данные (поля подстановки с возможностью правки до утверждения) ·
Версии (список с авторами, датами, комментариями, скачиванием файла каждой
версии) · Согласование (маршрут, кто и когда, комментарии) · Файлы (сканы,
подписанные экземпляры) · Связи · История.

#### 5.7.3. Создание документа из источника

Вызывается кнопкой «Создать документ» из заказа, сделки, производственного
заказа, складской операции или платежа. Диалог: тип документа, шаблон, язык.
Далее — предзаполненный черновик с возможностью правки, предпросмотр, сохранение.

#### 5.7.4. Шаблоны

Список: тип документа, язык, версия, статус, дата публикации.
Редактор: загрузка DOCX, список найденных плейсхолдеров, сопоставление с полями
системы (подсказка доступных полей из `/documents/templates/{uid}/fields`),
проверка на тестовой записи с предпросмотром результата, публикация.

Несопоставленные плейсхолдеры выводятся явным списком — публикация с ними
блокируется, иначе клиент получит документ с `{client.name}` в тексте.

#### 5.7.5. Типы документов

Настройка: код, наименование ru/uz, маска нумерации с предпросмотром
следующего номера, область счётчика, маршрут согласования (роли по шагам),
доступные шаблоны.

### 5.8. CRM

#### 5.8.1. Лиды

Таблица: дата, имя, телефон, email, источник, статус, менеджер, комментарий.
Фильтры: период, источник, статус, менеджер, «необработанные».
Действия: создать, назначить менеджера, конвертировать в клиента и сделку,
отклонить с причиной.

#### 5.8.2. Сделки — канбан и таблица

**Канбан:** колонки по стадиям воронки, в шапке колонки — количество и сумма.
Карточка: клиент, сумма, ожидаемая дата закрытия, менеджер, задачи, просрочка.
Перетаскивание между стадиями (по праву). Перевод в «проиграна» требует
указания причины — модальное окно с обязательным полем.

**Таблица:** номер, клиент, сумма, стадия, вероятность, ожидаемая дата, менеджер,
дата создания, дней в стадии.

#### 5.8.3. Карточка сделки

Шапка: номер, клиент, сумма, стадия, вероятность, ожидаемая дата, менеджер.
Действия: перевести по стадии, выиграть, проиграть, создать заказ, создать КП,
добавить задачу, зафиксировать активность.
Вкладки: активности (лента звонков, встреч, заметок в хронологии) · задачи ·
документы · заказы · файлы · история.

#### 5.8.4. Клиенты

Список: наименование, ИНН, телефон, менеджер, долг, лимит, последний заказ,
сумма заказов за период, статус.

Карточка: реквизиты, контактные лица, условия работы (тип цены, отсрочка,
лимит долга), и вкладки: сделки · заказы · документы · платежи · задолженность
(с возрастной структурой) · активности и звонки · задачи · файлы · история.

Превышение лимита долга — заметная отметка в шапке карточки и предупреждение
при создании нового заказа.

#### 5.8.5. Задачи

Список и календарь. Поля: тип, заголовок, клиент, сделка, срок, ответственный,
статус, результат. Фильтры: «мои», «на сегодня», «просроченные», по типу,
по ответственному. Быстрое закрытие с вводом результата.

#### 5.8.6. Отчёты CRM

Воронка (количество и сумма по стадиям, конверсия между стадиями),
по менеджерам, по источникам, причины отказов.

#### 5.8.7. Звонки

Лента: дата, направление, номер, клиент, менеджер, длительность, запись
(встроенный проигрыватель), связанная сделка, заметка.
ОТКРЫТО: провайдер телефонии. Экран делается на контракте, данные — из моков.

### 5.9. Администрирование

#### 5.9.1. Пользователи

Список: ФИО, логин, email, телефон, роли по компаниям, Telegram привязан,
статус, последний вход. Карточка: профиль, назначения ролей (роль + компания +
подразделение/склад + область видимости), активные сессии с возможностью
отзыва, журнал входов.

#### 5.9.2. Роли и права

Список ролей. Редактор роли — матрица прав: строки — права, сгруппированные
по модулям, колонки — флажок. Групповые переключатели на уровне модуля.
Рядом — список пользователей с этой ролью.

Экран должен быть читаемым: прав будет несколько сотен. Обязательны поиск по
правам, сворачивание групп и кнопка «показать только отмеченные».

#### 5.9.3. Справочники

Единый раздел со списком справочников (номенклатура, группы, склады, зоны,
места, единицы, валюты и курсы, статьи ДДС, счета, причины, участки, источники,
стадии воронки, типы цен). Общий табличный редактор с импортом и экспортом Excel.

#### 5.9.4. Настройки

По компаниям: реквизиты, логотип, базовая валюта, метод списания (FIFO /
средневзвешенная), правила автосписания материалов, сроки резервов, пороги
уведомлений, маршруты согласования, параметры нумерации, рабочий календарь
и смены.

#### 5.9.5. Журнал действий

Таблица: дата и время, пользователь, компания, источник (веб / мобильное /
бот / интеграция), сущность, действие, объект, IP. Разворот строки — что
изменилось: было / стало. Фильтры по пользователю, сущности, действию, периоду.
Экспорт.

## 6. Качество и приёмка фронтенда

### 6.1. Обязательно перед сдачей экрана

1. Скриншоты 360 и 1440, светлая и тёмная тема, сайдбар свёрнут и развёрнут.
2. Все пять состояний (загрузка, пусто, ошибка, нет прав, данные) — работают.
3. Проверка на узбекской локали: длинные подписи не ломают раскладку.
4. Проверка с клавиатуры: пройти основной сценарий экрана без мыши.
5. Таблица на 10 000 строк из мока не вешает вкладку.
6. Ошибки 403 / 404 / 409 / 422 обработаны осмысленно, а не общим «что-то пошло не так».

### 6.2. Автотесты

- Playwright-сценарии на ключевые пути: вход, создание заказа с проверкой
  остатка, приёмка сканированием, фиксация производственного этапа, проведение
  платежа с согласованием, генерация документа.
- **Pixel-diff эталоны** на принятые экраны (каталог `qa/`). Любая правка CSS
  сверяется с эталоном. Эталон обновляется только по осознанному изменению
  дизайна, и об этом пишется в отчёте.
- Юнит-тесты на форматирование денег, количеств и дат, на пересчёт единиц
  измерения и на расчёт сумм строки заказа.

### 6.3. Что считается невыполненной работой

- `position: absolute` с подогнанными пикселями вместо flex/grid;
- состояние таблицы не в URL;
- числа с точностью приведены к JS-number где-то по пути;
- кнопки нарисованы без учёта `permissions`;
- тексты в коде вместо словарей;
- экран не проверен на 360 px.

## 7. Передача работы

Результат передаётся zip-архивом с исходниками (без `node_modules`).
Внутри обязательно:

- `README.md`: как запустить, как переключить моки на реальный API
  (одна переменная окружения), какие сценарии покрыты тестами;
- `src/mocks/` — обработчики и фикстуры, по которым работает интерфейс;
- `src/lib/api-client.ts` — единая точка обращения к API: заголовки,
  обработка ошибок, повторы, `Idempotency-Key`;
- `qa/` — скриншоты-эталоны и Playwright-сценарии;
- список мест, где контракт API оказался неполным или неудобным — это вход
  для второго этапа.

Замена моков на реальный бэкенд не должна требовать правок в компонентах.
Если требует — слой доступа к данным собран неправильно.

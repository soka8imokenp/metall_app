# Откуда пришёл лид: подключение сайта

Для веб-мастера сайта METALL ASIA. Всё, что нужно сделать на сайте, — две
вставки. Код CRM при этом не меняется.

## 1. Получить ключ сайта

CRM → **Справочники** → **Приём с сайта** → «Добавить ключ».
Ключ публичный: он лежит в исходном коде страницы, и прятать его бессмысленно.
Если по ключу полезли роботы — ключ выключают и заводят новый.

В поле «Разрешённые адреса» впишите адрес сайта (`https://metallasia.uz`).
Пусто — принимаем заявки с любой страницы.

## 2. Вставить скрипт

Файл: `docs/site/metall-lead.js` этого репозитория. Положите его на сайт и
подключите на **всех** страницах, а не только там, где форма: метки собираются
в момент входа на сайт, а заявку оставляют позже и с другой страницы.

```html
<script>
  window.METALL_LEAD_KEY = 'сюда ключ из CRM';
  window.METALL_LEAD_ENDPOINT = 'https://metall-asia.cloudplus.uz/api/v1/public/leads';
</script>
<script src="/js/metall-lead.js" defer></script>
```

## 3. Подключить форму

Самый простой путь — добавить формe атрибут и назвать поля:

```html
<form data-metall-lead="callback">
  <input name="name" placeholder="Имя">
  <input name="phone" placeholder="Телефон">
  <textarea name="comment"></textarea>
  <button type="submit">Отправить</button>
</form>
```

Скрипт сам перехватит отправку, добавит скрытую ловушку для ботов и пошлёт
заявку в CRM. Результат приходит событиями на самой форме:

```js
form.addEventListener('metall-lead:ok', () => alert('Заявка принята'));
form.addEventListener('metall-lead:fail', (e) => alert(e.detail));
```

Если форма своя (Tilda, конструктор, своя валидация) — зовите напрямую:

```js
MetallLead.send({ name, phone, email, comment, formCode: 'calc' })
  .then(() => /* спасибо */)
  .catch((e) => /* показать e.message */);
```

`formCode` — какая это форма на сайте. «Заказать звонок» и «Рассчитать
стоимость» — разные заявки, и считать их лучше раздельно.

## 4. Проверить

1. Откройте сайт с меткой: `https://сайт/?utm_source=google&utm_medium=organic`.
2. Отправьте тестовую заявку.
3. CRM → **Обращения** → у заявки появится ссылка «Откуда пришёл»: источник
   «Поиск (SEO)», страница входа, первый и последний визит.
4. CRM → **Отчёты** → **Метки сайта** — заявка попадёт в строку этой кампании.

## Что приходит в CRM

| Поле | Откуда | Зачем |
|---|---|---|
| `utm_source/medium/campaign/content/term` | адрес страницы входа | канал, кампания, запрос |
| `gclid`, `yclid`, `fbclid`, `ysclid` | адрес | клик рекламной системы |
| страница входа и переход | браузер | какая страница привела |
| первое касание | localStorage, 90 дней | что привело впервые — это и есть SEO |
| `client_id` Метрики или GA | их cookie | чтобы вернуть конверсию обратно в аналитику |

## Чего это не ловит

- **Звонки.** Человек видит номер и звонит — меток в звонке нет. Решается
  либо отдельным номером на SEO-страницах, либо подменой номера (call
  tracking, платный сервис). Решение заказчика.
- **Заявки в мессенджеры** в обход формы.
- **Заход с другого устройства.** Нашёл с телефона, заявку оставил с
  компьютера — для CRM это два разных посетителя. Так у всех.

## Что сделано заранее на стороне CRM

- приём заявок открытым маршрутом `POST /api/v1/public/leads`;
- ключи сайта с ограничением по адресам страниц и частоте, ловушка для ботов;
- хранение обоих касаний и разбор меток по справочнику источников правилами;
- отчёт «Метки сайта» с двумя колонками обращений и деньгами;
- поле `client_id` аналитики — его хватит, чтобы позже выгружать офлайн-
  конверсии в Метрику и GA, когда заказчик даст доступ к счётчику.

## Порядок работ

1. **Фронтенд** — делает сторонний исполнитель (другой ИИ) по `05-FRONTEND.md` и
   `04-API-CONTRACT.md`. Работает на моках, повторяющих контракт.
2. **Передача** — Тагир присылает zip с проектом фронтенда.
3. **Бэкенд** — собираю я (dev1) по `06-BACKEND.md`, подключаю фронт к реальному API.

Пока фронтенд в работе, бэкенд не пишется. Контракт API при этом фиксируется
заранее и меняется только письменно: это единственный шов между двумя этапами,
и расхождение в нём стоит дороже всего остального.

## Принятый стек

Решение исполнителя по п.2.5 Договора — согласования с заказчиком не требует.
Версии сверены 23.09.2026.

| Слой | Технология | Версия | Почему |
|---|---|---|---|
| Веб-фронтенд | Next.js (App Router) + React + TypeScript | 16.3.x | SSR для тяжёлых таблиц, стабильный роутинг, широкая поддержка |
| UI | Tailwind CSS + shadcn/ui + TanStack Table/Query | текущие | быстрый набор плотных таблиц и форм |
| Мобильное | Expo / React Native | SDK 57, RN 0.86 | камера, сканер кодов, push — из коробки; переиспользование TS-типов |
| Бэкенд | NestJS + TypeScript | 12.1.0 / TS 7.0.2 | модульность, DI, единый язык с фронтом |
| БД | PostgreSQL | 18.x | RLS для двух компаний, numeric, партиции, оконные функции |
| ORM/миграции | Prisma + raw SQL на горячих запросах | текущие | типы из схемы, версионируемые миграции |
| Кэш, очереди | Redis + BullMQ | текущие | фоновые задачи, расчёты себестоимости, рассылка уведомлений |
| Файлы | S3-совместимое хранилище (MinIO на сервере заказчика) | — | фото, сканы, записи звонков, сгенерированные документы |
| Документы | DOCX через docxtemplater, PDF через headless Chrome | — | DOCX и PDF по договору обязательны |
| Боты | Telegraf | текущие | один бот с роутингом по ролям |
| Наблюдаемость | pino + OpenTelemetry + Prometheus | — | разбор инцидентов на проде |

**Уточнено 24.09.2026 по факту установки, а не по плану.** На момент старта в npm
стоит NestJS **12.1.0**, он и поставлен. Последствия, проверенные на сборке:

- Пакеты Nest 12 — чистый ESM (`"type": "module"`). Node 26 умеет `require(esm)`,
  но TypeScript отказывается компилировать такой импорт из CommonJS (TS1479) —
  ни при `node16`, ни при `nodenext`. Бэкенд переведён на ESM целиком:
  `"type": "module"` в `package.json`, `moduleResolution: nodenext`, расширение
  `.js` в относительных импортах, генератор Prisma с `moduleFormat = "esm"`.
- TypeScript 7.0 не отдаёт программный API компилятора — `nest build` на нём
  не работает и сам это сообщает. Собираем обычным `tsc -p tsconfig.json`;
  `emitDecoratorMetadata` он выдаёт, DI Nest работает (проверено: в выводе
  есть `design:paramtypes`, приложение поднимается и отвечает). `nest-cli.json`
  удалён как нерабочий. Вернуть CLI можно, откатив TypeScript до 6.x.
- Prisma: ставить строго `prisma@^7.10.0`. `bun add -d prisma` тянет 8.0.0-rc.

## Нерешённые вопросы (блокируют часть работ)

| Вопрос | Кого спросить | Что блокирует |
|---|---|---|
| Прошёл ли первый платёж | Артём | отсчёт 4 недель по договору |
| Сервер: где, какие мощности, когда доступ | клиент | развёртывание, приёмка |
| Образцы действующих документов клиента | клиент | конструктор документов (прямо оговорено в Спецификации) |

| Доступы и документация: 1С, REGOS, банк, телефония | клиент | весь раздел интеграций |
| Правила KPI и бонусов менеджеров | клиент | расчёт KPI в финансах |
| Мобильное: Expo-сборка или PWA | Артём / Тагир | объём работ по мобильному |

ответ и что именно он разблокирует. Таблица выше — только самое крупное.

чтобы ответ менял настройку, а не архитектуру.

# METALL ASIA — фронтенд

Vite 8 + React 19 + TypeScript 7 + Tailwind 4. Пакетный менеджер — `bun`.

## Запуск

```bash
bun install --frozen-lockfile
bun run dev            # http://localhost:5173
```

Проверка типов — только локальным компилятором проекта:

```bash
./node_modules/.bin/tsc --noEmit
```

`bunx tsc` тянет TypeScript извне проекта и падает на `vite/client` — не использовать.

## Переменные окружения

Файл `.env.local` в корне фронтенда, в git не попадает (`.gitignore`: `.env*`).

| Переменная        | По умолчанию | Смысл |
|-------------------|--------------|-------|
| `VITE_USE_MOCKS`  | `true`       | `false` — ходить в настоящий бэкенд. Любое другое значение оставляет моки. |
| `VITE_API_URL`    | `/api/v1`    | База API. При запуске бэкенда локально — `http://127.0.0.1:4000/api/v1`. |

Живой бэкенд:

```
VITE_USE_MOCKS=false
VITE_API_URL=http://127.0.0.1:4000/api/v1
```

В режиме моков форма входа показывает предупреждение жёлтым: данные ненастоящие.

## Связка с бэкендом

Бэкенд — `../backend`, порт 4000, слушает `127.0.0.1`. CORS открыт для
`http://localhost:5173` (переменная `CORS_ORIGINS` на стороне бэкенда).

Логины из сидов — в `../backend/prisma/seed.ts`; пароль общий, задаётся
переменной `SEED_PASSWORD` при посеве.

## Состояние экранов

Дашборд переведён на настоящий API: KPI-карточки, график и таблица плана
читают `GET /dashboard/summary` и `GET /dashboard/plan`.

Таблица плана работает **только на чтение**: в контракте
(`../docs/04-API-CONTRACT.md` §14.1) для неё определены лишь GET-эндпоинты.
Вкладки «Смены и персонал» и «ГОСТы и регламенты» источника данных не имеют
и показывают это явным состоянием, а не пустой таблицей.

Остальные разделы (продажи, склад, производство, финансы, документы, CRM,
админка) пока на фикстурах из `src/mocks/`.
